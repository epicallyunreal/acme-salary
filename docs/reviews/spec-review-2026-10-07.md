## Technical claims: verified correct

- Partial unique on SQLite: Django 6.1.2 emits `CREATE UNIQUE INDEX "one_open" ON ... WHERE "effective_to" IS NULL`; a second open record raises `IntegrityError`. Source: probe; Django 6.1 constraints docs ("may be implemented as unique indexes").
- `CheckConstraint(condition=...)` on 6.1.2: `effective_to = effective_from` rejected, so the half-open design keeps `>`. Source: probe.
- Decimal on SQLite: stored as `real` (2400000.37) and `integer` (150000.00); `F('gross') * F('rate')` compiles to `CAST((gross * rate) AS NUMERIC)`, computed by SQLite in floating point, returned as `Decimal('28571.4284047612')`; `Sum` returns `Decimal`. §4.1's wording (REAL in SQLite, SQL only to order and filter, quantise in Python) is accurate. Source: probe; Django 6.1 databases docs ("Decimal values are internally converted to the REAL data type").
- SQLite `OPTIONS` `transaction_mode`, `init_command`, `timeout` accepted by 6.1.2 and documented for 6.1. Source: probe; databases docs.
- The whole backend pin set runs together on Python 3.14.3: Django 6.1.2, DRF 3.18.3, SimpleJWT 5.5.1, django-filter 26.2, django-cors-headers 4.9.0, whitenoise 6.12.0, openpyxl 3.1.5, defusedxml 0.7.1, gunicorn 26.2.0, Faker 40.41.0, factory_boy 3.3.3, freezegun 1.5.5. Caveats found and cleared: SimpleJWT 5.5.1 (2025-07-21) predates its Django 6/py3.14 PR #959 (merged 2026-02-09, CI files only); factory_boy 3.3.3 declares Django 5.1 and its issue #1147 "TypeError in Django 6" was the reporter's own positional `save()`; freezegun's PR #594 "Support Python 3.14" is an open draft, yet `calendar.timegm` and SimpleJWT token creation under `freeze_time` worked. Source: `uv run` probe, PyPI, GitHub API.
- SimpleJWT: `ROTATE_REFRESH_TOKENS` and `BLACKLIST_AFTER_ROTATION` default False, access 5 min, refresh 1 day, blacklist app required; `{email, password}` login with `USERNAME_FIELD = "email"` returns 200 `{access, refresh}`; rotated-out refresh returns 401 "Token is blacklisted"; `TokenBlacklistView` serves `POST /auth/logout/ {refresh}`; `flushexpiredtokens` exists and is meant to run daily. ## Gaps and ambiguities an implementer would guess at

1. **Which packages are in the production image.** SPEC §1 lists "Faker (pinned to the patch), factory_boy, freezegun, pytest, ..." in one row that reads as the dev group; §14 builds with `uv sync --frozen --no-dev` and the entrypoint runs `seed_data`. If Faker lands in the dev group, the first boot on Fly crashes at the seed and the health check fails. Say: Faker main; factory_boy, freezegun, pytest*, ruff, pre-commit dev.
2. **`last_date` through import.** F1 lists `last_date` among identity fields and makes an identity change "`update`, identity fields only". Whether that runs the exit service (close the open record at `last_date + 1`, refuse with 409 when scheduled revisions follow) or writes the column, and whether a blank `last_date` on an exited employee un-exits (P1 through the UI), is unstated and absent from §7.
3. **Backdated exit.** F3 checks only `last_date >= joining_date`. A `last_date` before the open record's `effective_from` makes `effective_to <= effective_from` and the check constraint fires (probe: `IntegrityError`), a 500. Add the 400 rule.
4. **"Records that have ever been current are immutable" (§4.3)** while revise and exit write `effective_to` on them. Say: amounts, lines, `effective_from`, `bonus_annual`, `note` are immutable; `effective_to` is owned by the service.
5. **Number normalisation.** "thousands separators ... stripped, dot decimal only, comma decimal is an error" leaves `1,200` undefined (1200, or 1.2 in DE and NL). Define: a comma followed by exactly three digits with no dot is a separator; any other comma is the error.
6. **Upload rejections.** Status for row 10,001 and for a wrong extension or content type (§8 has 413 for bytes and nothing else); skip, unskip and discard on a batch not in `review` (only approve has the 409).
7. **Insight edge cases.** `quantiles` raises on an empty list (probe); `distribution` with p1 equal to p99 has zero-width bands; what `gender-gap` shows for `other` and `undisclosed`; whether `summary` with a filter that yields one person publishes that person's pay as the median (by-level hides min and max under five people, nothing else does).
8. **`updated_at`.** §5's `default=timezone.now` note covers `created_at`; an `auto_now` `updated_at` is set by `bulk_create` and by every save, and Employee is in the determinism scope. Say the service sets it, or exclude it from the dump.
9. **The determinism test's "two fresh databases"** inside one pytest session on in-memory SQLite: how, and whether a golden hash is committed (which also catches cross-machine drift, which two runs in one process do not).
10. **`set_exchange_rate`.** Arguments; a second rate with the same `effective_from` (unique constraint, 400 or error); a backdated `effective_from` where "closes the previous one" cannot hold; which pair's date the dashboard shows when five differ. Prior gap 10, still open.
11. **The directory annotation.** One rate per currency on `on` has to reach each row (a `CASE WHEN currency_code = ...` built in Python from the rate lookup is the obvious shape) and the record must be "current on `on`, else the latest" per employee, in SQL, for sort and filter. It is the one query the 300 ms target depends on; DESIGN.md must give it.
12. **`employee_code` assignment.** "next `ACME-NNNNNN`" after the maximum including imported codes? The seed's code range?
13. **Seed parameters.** `TAX` "flat recorded projection by country band" and `EMPLOYER_CONTRIBUTION` "8 to 20% by country" have no bands or per-country values; which April raises apply to an employee exited in 2022; "last record" for `include_exited` by `effective_from` or `version`.
14. **ImportRow.status `skipped`** overwrites the validation status; unskip must recompute it from `messages`.
15. **`currency` on the dashboard.** F5 "local when exactly one country is selected" reads as automatic; §8 reads as a parameter value. Which, and what `include_exited` defaults to.
16. **Directory `status` for future joiners** (neither active nor exited on `on`).
17. **Unknown names.** `GET /imports/template/?country=XX`, `GET /insights/unknown/`: 400 or 404.
18. **Refresh token in `localStorage`.** F8 chooses it; no DECISIONS entry says why not an httpOnly cookie. The client's security reviewer asks this first.
19. **`collectstatic`, `STATIC_ROOT`, asset caching** (technical claim 5). **`NUM_PROXIES`** (claim 7).
20. **Seed atomicity on first boot.** §14 runs the seed in the entrypoint under a 120 s health-check grace. Nothing says the seed is one transaction. A machine killed mid-seed leaves a non-empty Employee table, `--if-empty` then skips forever, and the site runs on a partial dataset.

## Risks

**Delivery**
- B3. The calendar, not the design, is the main risk.
- Step 1 depends on the owner: a Fly account with a card (no free tier beyond a trial), `flyctl` (absent here), the Cloudflare CNAME, and the `.dev` certificate before the browser will load anything.
- Each step close runs two suite passes and four agents (10 to 20 minutes), and under the current rules two of those agents raise Blockers the spec forbids fixing (B1, B2). Every `manage.py` call prompts (technical claim 2).
- Five libraries changed major version since March 2026; CLAUDE.md's Context7 instruction is the mitigation and it is installed.

**Performance**
- Reads have margin; the annotation in gap 11 is the only query that could miss 300 ms and it is measured only at step 8.
- Approve under 15 s holds only through the bulk entry point (§15 step 2). With `transaction_mode IMMEDIATE`, one worker and eight threads, a 15 s approve holds the write lock and other writers wait up to 20 s; with one user that is fine.
- Memory: parsing is negligible (1.6 MB); 10,000 staged rows held as Python objects before `bulk_create` are the unmeasured peak on a 512 MB machine.

**Deployment**
- `bom` (technical claim 4). A single volume with no replica (accepted in D17). First boot: migrate plus a seed measured "under 60 s" on a laptop, against a 120 s grace on a shared CPU (gap 20).
- Staged rows and audit rows are never purged; the volume is 1 GB.
